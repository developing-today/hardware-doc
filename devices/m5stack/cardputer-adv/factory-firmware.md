## Partition table

`partitions.csv`, verbatim:

```
# Name,   Type, SubType, Offset,  Size, Flags
nvs,      data, nvs,     0x9000,  0x4000,
otadata,  data, ota,     0xd000,  0x2000,
phy_init, data, phy,     0xf000,  0x1000,
factory,  app,  factory, 0x10000, 4M,
```

Observations:

* **A single `factory` app slot and no OTA slots**, despite an `otadata` partition existing.
  Over-the-air update is not possible with this layout.
* **4 MB of 8 MB is allocated.** Roughly 3.9 MB is unclaimed — which is exactly the room the
  community's memory-mapped-font trick uses (see [`projects-and-community.md`](projects-and-community.md)).
* Application base offset **`0x10000`**.

## ⚠ The dependency pins are stale

`repos.json` clones `M5GFX` at branch **`0.2.15`** and `M5Unified` at branch **`0.2.10`**, both
older than the current heads (`d91077b9`, `8530f537`). The shipped firmware therefore does not
correspond to any current checkout of those libraries. Diffing the pins against `HEAD` is the
correct move when the factory image behaves differently from your build — it is how the
PaperMono pass found an M5GFX waveform change, and the same discipline applies here.

## Getting the binary

Two published routes, **neither exercised in this pass**:

1. **EasyLoader** — `https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1178/Easy_Loader_for_Cardputer-Adv.exe`
   (a Windows self-extracting flasher; the PaperMono pass established that these are named
   `<SKU>-…_0x00.exe` and contain the image plus esptool).
2. **M5Burner API** — `burner.m5stack.com/api/v1/firmwares/{id}` and
   `/versions/{vid}/download`. Per [`vendors/m5stack`](../../../vendors/m5stack/README.md) §4
   the `/api/v1` prefix is public while `/api` returns 401. **No firmware id was resolved for
   the Cardputer ADV in this pass** — that is the main gap in this file.

With a binary in hand, the useful things to extract are `esp_app_desc_t` at **`0x10020`**
(`project_name`, `app_version`, `build_date`/`time`, `idf_version`) and the partition table at
`0x8000`. `hardware-doc/tools/esp_image_info.py` does this.

## Recovery

Re-flash over USB in download mode (switch OFF → hold G0 → power → release). There is no OTA
slot and no factory-reset button. The `nvs` partition at `0x9000` holds settings; erasing it
resets configuration without touching the application.
