# Context: www.wch-ic.com (and www.wch.cn) are Vue single-page apps that return
# *** HTTP 200 with a ~4305-byte HTML shell for EVERY path they do not recognise ***,
# including every https://www.wch-ic.com/downloads/<NAME>_PDF.html documentation URL and every
# https://www.wch-ic.com/downloads/file/<id>.html page. Nothing in the response distinguishes
# "wrong URL" from "here is your document". This is why the 2026-08-21 first pass recorded the
# CH445P datasheet as unobtainable and the USB-UART bridge U10 as unidentifiable.
#
# THE ROUTE THAT WORKS (no User-Agent substitution needed; a plain default UA is fine):
#   1. GET https://www.wch-ic.com/api/official/website/files/getFilesById?id=<N>
#      -> JSON: {"code":0,"data":[{"id":N,"name":"CH440DS1.PDF","version":"3.2",
#                                  "uploadTime":"...","size":"307KB","content":"...",
#                                  "scope":"CH440G, ..., CH445P, ..."}]}
#      Enumerate N over roughly 1-800 and match on `name` OR on `scope`. The `scope` field is the
#      key: WCH publishes ONE document per *family*, named after the family's FIRST member, so a
#      part number can be absent from every document title while appearing in a scope string.
#   2. GET https://www.wch-ic.com/download/file?id=<N>   -> the actual PDF. Validate %PDF magic.
#   Throttle to <= ~24 concurrent requests; above that the API times out silently.

  TOOLING NOTE FOR THE NEXT AGENT
  -------------------------------
  This machine has NO pdftotext / mutool / qpdf / gs, and no system pypdf. Working
  recipe used for every PDF in this pass:
      python3 -m venv /tmp/opencode/v
      /tmp/opencode/v/bin/pip install pypdf cryptography
      /tmp/opencode/v/bin/python -c "import pypdf; ..."
  The `cryptography` package is MANDATORY for the WCH datasheets -- CH340DS1.PDF is
  AES-256 encrypted with an EMPTY user password and pypdf raises
  "DependencyError: cryptography>=3.1 is required for AES algorithm" without it.

  A KiCad .kicad_sch net extractor was written to /tmp/opencode/ksch.py for this
  pass (S-expression parse -> wire/label/pin union-find -> netlist). It is NOT
  committed. Two calibration facts worth re-deriving if you rebuild it:
    1. A lib_symbol pin's (at x y ang) is ALREADY the connection point; do NOT add
       (length). Global position = (sym_x + rot(px,py), sym_y - rot_y). The Y is
       NEGATED because lib space is Y-up and sheet space is Y-down.
    2. Soldered's newer sheets FLATTEN multi-unit lib_symbols to top level as
       "0603R_1", "0603R_14", ... with the parent "Soldered symbols:0603R" absent.
       Match lib_id basename OR basename+"_<digits>" and merge, or every passive
       silently drops out of the netlist and nets look disconnected.
